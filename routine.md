# Routine: тексты утренней подборки

Ты пишешь все тексты утренней Telegram-подборки. В 08:00 по Минску GitHub Actions заберёт их,
добавит погоду, курсы валют и карточку-инфографику и разошлёт каждому получателю.

## Что сделать

1. Прочитай `config.json` (`city`, `language`, `timezone`, разделы `intro_sections`, `sections`,
   `outro_sections`) и `state.json` (получатели: `users` — chat_id → `name`, `interests`, `zodiac`).
2. Узнай сегодняшнюю дату и день недели в поясе `timezone`: `TZ=Europe/Minsk date '+%F %A'`.
3. Прочитай архив прошлых выпусков (см. «Без повторов»):
   `git fetch origin claude/shared && git show origin/claude/shared:history.json` (нет ветки или файла — архив пуст).
4. Собери через веб-поиск **общую часть** — разделы `sections` строго в указанном порядке. Описание
   каждого раздела в `config.json` — это требования к нему (что брать, что НЕ брать, какие поля указывать).
5. Для **каждого** получателя из `state.json` напиши личные тексты (см. «Личные части»).
6. Найди **открытку «С добрым утром»** и **мем дня** (см. ниже).
7. Запиши всё в `digest.json` в корне репозитория (формат ниже) и проверь, что JSON валиден:
   `python3 -c "import json; json.load(open('digest.json'))"`.
8. Допиши сегодняшний выпуск в `history.json` (см. «Без повторов») и проверь, что он валиден.
9. Опубликуй только эти файлы в ветку `claude/shared`:
   ```bash
   git checkout -B claude/shared
   git add -f digest.json history.json
   for f in postcard.jpg postcard.png meme.jpg meme.png; do [ -f "$f" ] && git add -f "$f"; done
   git commit -m "Digest $(TZ=Europe/Minsk date +%F)"
   git push -f origin claude/shared
   ```
   Другие файлы не меняй, pull request не создавай.

## Формат `digest.json`

```json
{
  "date": "YYYY-MM-DD",
  "shared": "текст общей части: все разделы sections подряд",
  "highlights": [
    {"title": "Концерт группы X", "when": "сегодня 19:00", "where": "Филармония"}
  ],
  "personal": {
    "<chat_id>": {"intro": "...", "for_you": "...", "outro": "..."}
  },
  "default": {"outro": "..."},
  "postcard": {"url": "https://...", "source": "https://..."},
  "meme": {"caption": "", "url": "https://...", "source": "https://..."}
}
```

- `highlights` — 2–3 самых интересных события **сегодня** из общей части (мероприятия, фильм) для
  карточки-инфографики. Простой текст без HTML и эмодзи: `title` до 38 символов, `when` и `where` — по нескольку слов.
- `personal` — ключ каждого получателя из `state.json` → `users`, строкой, как там.
  - `intro`: короткое приветствие по имени (`name`), затем разделы `intro_sections` (если список пуст — только приветствие).
  - `for_you`: только если у получателя есть `interests`. Раздел «🎯 Для тебя» — 2–4 пункта по его
    интересам: из общей части или найденное дополнительно, со ссылками. Нет интересов — пустая строка.
  - `outro`: разделы `outro_sections`.
  - Род в обращениях и комплименте определи по имени; если непонятно — нейтральные формулировки.
  - Тексты разным получателям — разные: не копируй приветствие и комплимент от одного к другому.
- `default.outro` — разделы `outro_sections` без имени и в нейтральном роде: для тех, кто подпишется
  после твоего запуска.
- `shared`, `intro`, `for_you`, `outro`, `default.outro` — в Telegram-HTML (см. «Формат текстов»);
  `postcard`, `meme`, `highlights` — простой текст.

## Без повторов

`history.json` в ветке `claude/shared` — архив того, что уже уходило подписчикам:

```json
{"days": [{"date": "YYYY-MM-DD", "news": ["url", ...], "events": ["название", ...], "films": ["название", ...],
           "evening": "название", "places": ["название", ...], "postcard": "url", "meme": "url"}]}
```

- Перед сбором прочитай его и не повторяй то, что там уже есть:
  - новости (по ссылке и по сути), мировые и милые новости — никогда;
  - открытку и мем — никогда (сравнивай URL и саму картинку);
  - «Куда сходить вечером» и «Новое место недели» — не советуй то же, что последние 14 дней;
  - фильм, который уже был в «Новинках кино», больше не называй новинкой;
  - событие из афиши, которое уже показывали, повторяй только если оно сегодня или завтра — с пометкой
    «напоминаем»; иначе пропусти, чтобы освободить место новому.
- После сбора добавь в `days` запись за сегодня (все поля по тому, что ушло в выпуск) и оставь только
  последние 21 день.

## Открытка «С добрым утром»

- Каждый день — новая максимально кринжовая открытка «С добрым утром» в духе бабушкиных рассылок
  в мессенджерах: блёстки, розы, котики, чашка кофе, закат, витиеватый шрифт, пожелания добра.
  Чем кринжовее, тем лучше. Не повторяй вчерашнюю (не бери ту же картинку по URL).
- Скачай её в корень как `postcard.jpg` (или `postcard.png`) и проверь `file postcard.*`: картинка до 10 МБ.
  Не получилось — не создавай файл, но укажи `url`.
- В `digest.json` → `postcard`: `url` — прямая ссылка на картинку, `source` — страница, где нашёл.

## Мем дня

- Свежий мем-картинка (за последние дни) для русскоязычной аудитории 20–35 лет — острый и упоротый.
  Приоритет — злой, дерзкий, циничный юмор: чёрный юмор, взрослые шутки, стёб над бытом, работой, отношениями,
  деньгами, государственными и корпоративными абсурдами, проклятые картинки и сюр с неприятным послевкусием.
  Милые и «ламповые» мемы (котики, закрутки, бабушкины приколы) — нет: для доброго есть открытка и милые новости.
  Если выбираешь между «смешно, но безопасно» и «смешно и остро» — бери острое. Главное — реально смешно и не баян.
  Не бери мемы, где смысл — в длинном тексте мелким шрифтом.
- Скачай картинку в корень репозитория как `meme.jpg` (или `meme.png` для PNG) и проверь, что это
  действительно картинка до 10 МБ: `file meme.*`. Не получилось скачать — просто не создавай файл.
- В `digest.json` → `meme`: `url` — прямая ссылка на картинку (запасной путь, если файла нет),
  `source` — страница, где нашёл, `caption` — подпись к мему, если без неё не смешно (иначе пустая строка).
- Не нашёл подходящий — не добавляй поле `meme` вовсе.

## Как искать

- Ограничений по числу поисков нет: ищи столько, сколько нужно для хорошего результата.
  Открывай страницы, а не только сниппеты, и перепроверяй даты, время, место и цены по первоисточнику
  (сайт площадки, кинотеатра, организатора, официальная афиша).
- Источники: местные новостные сайты, городские афиши, сайты кинотеатров и театров, соцсети города.
- Новости — только за последние сутки; мероприятия — на ближайшие 7 дней, уже прошедшие не включай.
- Опирайся только на найденное, ничего не выдумывай. Если по разделу мало настоящего — лучше меньше.
- Погоду и курсы валют не пиши — их добавит workflow.

## Формат текстов

- Язык — из `language`.
- Telegram-HTML, НЕ Markdown. Разрешены только теги `<b>`, `<i>`, `<a href="...">`,
  `<blockquote expandable>`; других тегов нет, все теги закрыты. Символы `&`, `<`, `>` в самом тексте
  экранируй как `&amp;`, `&lt;`, `&gt;`.
- Заголовок раздела: эмодзи + `<b>Название</b>` на отдельной строке. Пункты через «•».
- Ссылки не голыми URL: делай ссылкой название пункта или ключевые слова —
  `<a href="https://...">«Сильва»</a>`.
- Разделы-списки (новости Витебска, мировые новости, афиша для взрослых и для детей, кино, план на выходные)
  прячь под спойлер: заголовок снаружи, пункты внутри `<blockquote expandable>…</blockquote>`.
  Милые новости, «Куда сходить вечером» и «Новое место» — открытым текстом.
- Внутри раздела не ставь пустых строк; между разделами — ровно одна пустая строка (по ней бот
  режет длинные сообщения, не разрывая теги).
- Каждая новость: 1–2 предложения в кратком ироничном, юмористическом ключе, ссылка — на ключевых словах.
  Шутим над подачей, а факты (что, где, когда, цифры) — точные.
- Если по разделу ничего стоящего не нашлось — так и напиши одной строкой.
- Без комментариев о поиске.
- `shared` — не длиннее 3000 видимых символов (без тегов и адресов ссылок; свёрнутые блоки тоже считаются),
  а `intro` + `for_you` + `outro` — не длиннее 900: вместе это должно влезть в одно сообщение Telegram (4096).
  Проверь перед записью: `python3 -c "import json,re; d=json.load(open('digest.json')); print(len(re.sub(r'<[^>]+>','',d['shared'])))"`.

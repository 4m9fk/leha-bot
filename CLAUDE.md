# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Telegram-бот без сервера: GitHub Actions раз в день запускает `digest.py`, который собирает утреннюю подборку по Витебску (шутка, погода, новости, афиша, комплимент) через Claude API с веб-поиском и отправляет её в Telegram. Весь код — один файл `digest.py`, поведение настраивается через `config.json`. Документация и тексты бота — на русском.

## Команды

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=... TELEGRAM_BOT_TOKEN=... INVITE_CODE=...
DRY_RUN=1 python digest.py   # напечатать подборку в stdout, ничего не отправлять
python digest.py             # реальная отправка в Telegram всем получателям
```

Тестов, линтера и сборки нет. `DRY_RUN=1` — основной способ проверить изменения: он не трогает Telegram (для него `TELEGRAM_*` не нужны), подменяет получателей одним фиктивным с именем «Друг» (одна генерация) и пробрасывает исключения вместо отправки сообщения об ошибке. Для DRY_RUN всё равно нужен `ANTHROPIC_API_KEY`, и каждый запуск стоит денег (веб-поиск, ≈ $0.05–0.15). SDK `anthropic>=1.8` (нужен `output_config`). Локальный `python3` на macOS может быть 3.9 — код требует 3.10+ (`int | None`, walrus в comprehension).

## Архитектура `digest.py`

Поток `main()`: `load_state()` → `ensure_names()` → `generate_shared()` **один раз** → для каждого получателя `generate_personal()` → `send(chat_id, intro + shared + outro)`. Разделение ради цены: дорогая часть с веб-поиском (`config.json["sections"]` — погода, новости, афиша, кино) общая для всех, а `intro_sections`/`outro_sections` (приветствие, шутка, комплимент) — дешёвый запрос без инструментов со structured output `{intro, outro}`; ему передаётся общая часть, чтобы шутка могла её обыграть. Если личная часть упала — уходит общая с простым «Доброе утро, <имя>!».

- **Состояние** — `state.json` в корне репозитория: `{"users": {chat_id: {"name", "awaiting_name"}}}`. Workflow коммитит его обратно после запуска, иначе получатели и имена теряются. `load_state()` добавляет `TELEGRAM_CHAT_ID` (если задан) как получателя без приглашения и мигрирует старый формат с одним `name` на верхнем уровне.
- **Подписка** — только по deep link `t.me/<бот>?start=<INVITE_CODE>`: бот получает `/start <код>` и добавляет chat_id. Сообщения из незнакомых чатов и `/start` с неверным кодом молча игнорируются. Пустой `INVITE_CODE` отключает подписку.
- **Знакомство (`ensure_names`)** — читает входящие из всех личных чатов через `getUpdates` (long polling, без вебхуков). У получателей без имени, которых ещё не спрашивали, спрашивает имя и ждёт ответа до `name_wait_minutes` — только от спрошенных в этом запуске (множество `asked`); ответ на вопрос из прошлого запуска подхватывается в начале следующего. Команда `/name <имя>` меняет имя; она обрабатывается только в начале следующего запуска (Telegram хранит апдейты 24 часа). В конце offset подтверждается отдельным вызовом `getUpdates`, чтобы сообщения не обрабатывались повторно.
- **Погода** — Open-Meteo (без ключа): мин/макс за день, температура в 08/13/18 и интервалы осадков с 6 до 24 часов (`rain_windows()`: час считается дождливым при вероятности ≥ `RAIN_PROBABILITY` или осадках ≥ 0.1 мм; соседние часы склеиваются, тип осадков по `WMO` берётся из часа с пиковой вероятностью). При ошибке в промпт уходит строка с просьбой найти прогноз через веб-поиск, а не исключение.
- **Генерация** — `ask_claude()` — общая обёртка над `messages.create`. Общая часть использует `web_search_20260209` (динамическая фильтрация результатов — меньше входных токенов; требует Sonnet 5/Opus, на Haiku не работает) с `user_location` и лимитом `max_searches`. `country` в `user_location` передаётся только если задан в конфиге: код `BY` веб-поиск отклоняет с 400. Цикл до 10 итераций продолжает запрос при `stop_reason == "pause_turn"` и склеивает текст **всех** кусков. `max_tokens=16000`: с 8000 пропадал последний раздел, вероятно из-за обрыва ответа; выше ~21000 SDK без стриминга откажет. В лог на каждый запрос пишется `stop_reason`, суммарные `input_tokens`/`output_tokens`, `web_searches` и `chunks` — по ним считать цену; при `max_tokens`/`pause_turn` — предупреждение о неполном ответе.
- **Вывод** — обычный текст без Markdown (так требует промпт; `parse_mode` не задаётся). `split_message()` режет по строкам под лимит `TG_LIMIT = 4000`.
- **Ошибки** — сбой у одного получателя не мешает остальным: ему уходит «⚠️ Не удалось собрать подборку…» (если не получается и это — например, бот заблокирован — ошибка только логируется), а в конце процесс завершается с кодом 1.

## Деплой

- Секреты GitHub Actions: `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `INVITE_CODE`, необязательный `TELEGRAM_CHAT_ID`.
- Workflow `.github/workflows/digest.yml`: запуск по `cron` (в UTC; `0 5 * * *` = 08:00 по Минску) и вручную через `workflow_dispatch`. После скрипта шаг с `if: always()` коммитит изменившийся `state.json`, поэтому нужен `permissions: contents: write`. `timeout-minutes` должен покрывать `name_wait_minutes` плюс генерацию.
- Модель задаётся в `config.json` (`claude-sonnet-5` по умолчанию, `claude-haiku-4-5` — дешевле). Если API ругается на модель или `web_search_20250305`, сверь актуальные названия с документацией Anthropic.
